# pele-animate.danielkimdev.com: Site, Docs and Agent Skills Plan

Plan for turning `pele-animate` from a tool built for one team's docs into a public package that outside
developers and coding agents can adopt on any project: proper docs in the repo, a landing site with a
playground, and installable agent skills. Modeled on `toonstrip/SITE_DEV_PLAN.md` (same hosting, same
sibling-site conventions); differences from toonstrip are called out in §4 and §12.

Status (2026-10-24): **S0, S1 and S2 are done; S3 onward is on hold** until upstream answers (§1, §10). What was built:

- **S0:** pnpm workspace (`.`, `site`; `npm pack` file list identical before and after the migration), `.node-version`,
  `.github/workflows/ci.yml` (`pnpm test` + `pnpm build`), root `wrangler.toml` (`site/build`), and a placeholder `site/`.
  **Not done:** the Cloudflare Pages project itself (dashboard step for Daniel: connect the repo, root `/`, build command
  `pnpm build`, output `site/build`).
- **S1:** `types/` wired through `exports`; the 16 `docs/*.md` pages (shipped in npm); README reduced to a quickstart;
  `docs/migrating.md`; `scripts/check-docs.mjs` renders every Mermaid fence and checks icon names. **Not done:** the API-drift
  check (§11) and an outside-developer run of the docs exit criterion.
- **S2:** `skills/pele-animate` (with `verify.js` and a generated `references/categories.md`) and `skills/diagram-step-order`, shipped in
  npm. Exit criterion met by a fresh subagent in an empty Vite app using only the installed skill; its feedback was folded in.
- Recommended answers in §13 were applied (single-source docs, pnpm, skills in npm, no check CLI, short preset section,
  KO later). Nothing is published to npm yet: the next release is 0.14.0. Nothing here is built. **Framework decided 2026-10-24: SvelteKit 3 (Svelte 5) with
`adapter-static`**, after spiking SvelteKit and Nuxt 4 + Nuxt Content against Astro; evidence in
`SITE_FRAMEWORK_RESEARCH.md`. Open decisions are collected in §13.

## 0. Mission and non-goals

**What pele-animate is, in plain words:** it makes a Pele diagram explain itself one step at a time. You choose the
order things appear in, readers can step through it with buttons or the keyboard, and any node can carry an icon from a
large set. **What it is not:** a theme or visual-style package. Others cover looks; we cover step order, step-by-step
playback and icons. Every page, the README and the site hero use this wording (see §12, overlap with community looks).

One job: get a developer, or their coding agent, from "what is this?" to an animated diagram rendering in their
own project in one sitting, without guessing. Surfaces, in visitor order:

1. **Intro** (`/`): what it is, a live animated hero (a real diagram, not a GIF), 30-second install.
2. **Docs** (`/docs/*`): every concept as Mermaid source next to the animated result it produces.
3. **Icons** (`/icons`): searchable browser for all ~4,400 bundled icons, copy-ready `@{ icon }` snippets.
4. **Playground** (`/playground`): edit Mermaid, watch it animate, tune the theme, share by URL.
5. **Changelog** (`/changelog`) and **agent surfaces** (`/llms.txt`, `.md` siblings, skills; §7).

Non-goals:

- Not a Pele replacement. Pele (kepano / Obsidian, MIT) does the layout and SVG; we add animation, icon packs and step
  playback. The site credits Pele prominently and links to pele.run for plain Pele questions.
- No AI features on the site (same rule as toonstrip). Agents are served by files, not by a chat box.
- No accounts, no saved diagrams, no server state. Sharing is a URL hash.
- No DoveRunner-internal identifiers anywhere (public repo, company boundary). The optional `preset-doverunner`
  pack is documented as one pack among others, with generic examples.
- Not a framework-wrapper project. Recipes only; no `pele-animate/react` until someone needs it.

## 2. Repo layout

Keep the published package at the repo root so `exports` paths and consumers do not change. Add a private `site/`
workspace member and a real `docs/` folder.

```
pele-animate/
  package.json            # published package (unchanged `files` whitelist: site/ and docs/ are not shipped)
  pnpm-workspace.yaml     # packages: ['.', 'site']   (S0 migrates from npm; see §12)
  docs/                   # THE docs: Markdown, read on GitHub AND rendered by the site (§4)
  skills/                 # agent skills, shipped in the npm package and fetchable from GitHub (§7)
    pele-animate/SKILL.md
    diagram-step-order/   # moved from .claude/skills; the old path becomes a symlink or copy for this repo's own use
  site/                   # SvelteKit app (adapter-static), private: true
  wrangler.toml           # at repo ROOT: name = "pele-animate", pages_build_output_dir = "site/dist"
  DESIGN.md               # site look and feel (written in S2; not duplicated here)
  SITE_DEV_PLAN.md        # this file
```

`site/` depends on the root package as `workspace:*`, so the site always dogfoods `main`. The version badge reads the
root `package.json` at build time.

## 4. Docs: one source in `/docs`, used by the repo and the site

This is the main departure from toonstrip, which keeps `docs/*.md` for GitHub and a separate MDX set for the site.
Two copies drift; for a smaller package we use one.

### 4.1 Rules

- Docs are plain Markdown files in `docs/`, one folder level at most. Frontmatter: `title`, `description`, `order`,
  `section`. GitHub ignores it (renders as a small table), the site uses it for sidebar and prev/next.
- Links between docs are relative `.md` links (`[icons](./icons.md)`) so they work on GitHub; the site's loader
  rewrites them to `/docs/icons/`.
- The site loads them with a Vite `import.meta.glob` pointed at `../docs` (§3). No MDX in `docs/`, no site-only syntax that
  breaks GitHub rendering.
- **Live examples** use a fenced block with a meta flag: a ```` ```mermaid live ```` fence is a normal code block on
  GitHub (Mermaid renders it there as a diagram) and, on the site, a remark plugin replaces it with the
  `CodeAndStrip` component: highlighted source, the animated result, "Open in playground" with the source in the hash.
  The code shown and the diagram shown come from the same fence and cannot disagree.
- Examples must be generic (client, API, queue, database, cloud). No DoveRunner names.
- Generated pages are never hand-edited: the icon index (`docs/icons.md` lists categories and counts; the full
  searchable list is the site `/icons` page and `icons.json`), and the API table check (§11).
- `README.md` shrinks to: what it is, one animated image, install, a 15-line quickstart, links into `docs/`. The long
  API and icon prose moves into docs pages. It is also what npm shows, so it stays self-sufficient for the quickstart.

## 5. Site surfaces

### 5.1 Intro (`/`)

Hero is a live diagram that plays on load and replays on click (step mode available), with the §0 one-liner under it.
Below: three short proofs (you set the order, readers step through it, 4,400 icons to pick from), the install block (npm, pnpm, yarn, bun), a
"Pele vs Mermaid.js vs pele-animate" honest comparison (step order, step playback and icon packs are ours; layout, size and looks are Pele's or other add-ons'), and
credits (Pele, Tabler). No marketing claims that are not measured; bundle numbers come from the build.

### 5.2 Docs (`/docs/*`)

Sidebar from `section` + `order`, prev/next, ToC, "Edit this page on GitHub" (points at `docs/*.md`),
copy-as-Markdown button on every page (the `.md` sibling, §7).

### 5.3 Icons (`/icons`)

Search box (name and Tabler tags), category chips (36), virtualized grid, click to copy `A@{ icon: "name",
form: "square", h: 88 }`, a stroke-width slider bound to `--pa-stroke`, and the import line for the category
(`import 'pele-animate/tabler/devices'`). Shows the `doverunner-*` pack as its own chip with the same behavior.
Backed by `icons.json` (S3 extends `build-tabler.mjs` to also emit `{ name, category, tags }`).

### 5.4 Playground (`/playground`)

Layout follows toonstrip's renewed playground: editor and controls on top, full-width preview below, per-section scroll,
tabs under 900 px.

- **Editor**: CodeMirror 6, Mermaid source, with `@{ icon: "` name completion from `icons.json`, lint for unknown icon
  names and bad pins (`parseOrder` is exported and cheap).
- **Preview**: the real `mount()` + `watch()`; replay button; step-mode toggle; width slider (reflow is a Pele feature
  worth showing); light/dark toggle.
- **Controls**: `--pa-stroke` slider, `--pa-solid` / `--pa-light` color pickers, `controls: false` toggle.
- **Examples**: a menu populated from the `live` fences in `docs/` (single source again).
- **Share**: `lz-string` hash; "Copy Mermaid", "Copy as HTML snippet" (a ready `<pre>` + script), "Download SVG" (the
  settled final frame, no animation).
- **Must not**: execute user JavaScript, fetch remote URLs from diagram source, persist anything server-side. Pele's
  size limits and sanitizing stay on; surface Pele's errors inline instead of hiding them.

### 5.5 Changelog (`/changelog`)

Rendered from the root `CHANGELOG.md` (Keep a Changelog, already public) plus an RSS feed. The breaking-change entries
link to `migrating.md`.

## 6. Design

A separate `DESIGN.md` (written in S2) defines the visual system. Constraints decided now:

- The look comes from the product: the lavender scene, `--pa-solid` purple, thin line icons; the site's own chrome is
  quiet so diagrams are the loudest thing on the page.
- Visibly distinct from pele.run so nobody mistakes it for the upstream project; footer states "built on Pele by
  kepano (MIT), not affiliated".
- Light and dark, reduced-motion respected everywhere (the hero too), 16 px gutters, no horizontal scroll at phone width.
- Fonts self-hosted at build (Fontsource packages), not loaded from a third-party host.

## 7. Agent surfaces and skills

Goal: an agent in a target project, given only npm or a URL, uses the package correctly and cannot invent icon names or
pin syntax.

### 7.1 Machine-readable site output

- `/llms.txt` (index) and `/llms-full.txt` (all docs concatenated), generated from `docs/`.
- Every docs page also served as `<page>.md` (Cloudflare Pages Function or build-time copy; same pattern as
  `docs-starlight`'s agent-readiness endpoints; build-time copy preferred since there is no server).
- `/icons.json`: `{ version, icons: [{ name, category, tags }] }`, plus the `doverunner-*` names. This is the antidote
  to hallucinated names.
- `/changelog.xml` RSS.

### 7.2 Skills (`skills/`, shipped in the npm `files` list)

| Skill | Purpose |
|---|---|
| `pele-animate` | Adopt the package in a target project. Detect framework, install `pele` + `pele-animate`, wire the three imports and the client-only mount, pick icon packs, write diagrams, theme, verify. Hard rules: icon names come from `icons.json` or `node_modules/pele-animate/tabler/*.js`, never from memory; pins use `%% pa:` exactly as in `step-order.md`; always verify by rendering. Mirrors toonstrip's SKILL: shape reference first, workflow last. |
| `diagram-step-order` | Existing skill, moved and generalized (review step order against the surrounding page text). Already uses a `steps.js` probe. |

Details:

- Skills live at `skills/<name>/SKILL.md` with `references/` for long tables (generated icon category list, pin cheat
  sheet) so SKILL.md stays short.
- **Verification is part of the skill**: render the page headless (Playwright or `agent-browser`), assert no empty
  `svg.pele-icon[data-icon]` and no fallback squares for names the user chose, and read `svg.paSteps`. The skill ships a
  tiny probe script for that, like `diagram-step-order/steps.js`.
- **Distribution**: (a) in the npm package, so `node_modules/pele-animate/skills/...` exists in every target project;
  (b) `curl` from GitHub raw, documented in `agents.md`; (c) a paste-ready `AGENTS.md` snippet (10 lines) for projects
  without skill support. A Claude Code plugin marketplace entry is optional and later.
- **Optional CLI** `npx pele-animate check <file>`: validates icon names against the installed packs and pins via
  `parseOrder`, exits 1 with every problem listed (toonstrip's CLI `FAIL:` style). Build it only if the skill's verify
  step proves clumsy without it; it is the one new runtime surface, so it is S5-optional (§10).
- Test the skills like code: a fresh agent in an empty Vite app must reach a working animated diagram using only the
  skill (§11).

## 8. Deployment (Cloudflare Pages)

Match `toonstrip` unless a reason is written here.

- Pages project `pele-animate`, GitHub integration, root directory `/`. Push to `main` = **production deploy** (this
  repo joins the deploy-on-push list in the basecamp `AGENTS.md` when the domain goes live; update it then).
- Build command (dashboard-only): `pnpm build`; output `site/build` (adapter-static's default); `packageManager` pinned in root `package.json`;
  `.node-version` at the root.
- Watch paths: `site/**`, `docs/**`, `skills/**`, `*.js`, `tabler/**`, `CHANGELOG.md`, `pnpm-lock.yaml`.
- `wrangler.toml` at the repo root (`name`, `compatibility_date`, `pages_build_output_dir = "site/build"`); it overrides the
  dashboard's output setting, so keep them equal.
- Domain: CNAME `pele-animate.danielkimdev.com` in the existing `danielkimdev.com` zone, attached only in the last
  phase. `pele-animate.pages.dev` and branch previews exist from S0 so every phase is checked on real hosting.
- `public/_headers`: immutable cache for `/_app/immutable/*`; CSP `'self'` plus the analytics beacon; a short cache for
  `/icons.json` and `/llms*.txt`.
- No Pages Function at launch. Short-link sharing is deferred like toonstrip's (hash links first).

## 11. Testing

- **Docs examples**: a script extracts every ```` ```mermaid ```` fence from `docs/` and renders it with Pele in Node
  (confirmed working in Node on 2026-10-24); fails on parse errors and on unknown `@{ icon }` names.
- **API drift**: a script compares `Object.keys` of each package export with the names in `docs/api.md` and `.d.ts`.
- **Links**: internal link check on the built site plus relative-link check on `docs/` (GitHub reading).
- **E2E (Playwright)**: docs live example animates; `/icons` search and copy; playground edit, share round-trip,
  replay, stroke slider changes computed `stroke-width`; reduced-motion disables motion.
- **Budgets** (`check-budgets` like toonstrip): intro page JS, playground island, and zero fetches of unused Tabler
  categories.
- **Skill test**: scripted fresh-project run (empty Vite app, agent given only the skill) recorded in `WORKLOG.md`.
- Library CI stays fast: site E2E only with `SITE_E2E=1`.

## 12. Risks and open questions

- **pnpm migration** touches a package already published from npm. Low risk (`files` whitelist unchanged), but verify
  `npm pack --dry-run` file list is identical before and after S0.
- **SvelteKit costs.** The spike measured 93 KB of uncompressed JS on a near-empty landing page (Astro's sources claim
  none by default) and shows docs infrastructure Astro or Nuxt Content would provide (content loader, Shiki, sitemap,
  RSS, `llms.txt` endpoints) must be written by hand. Mitigation: budget the landing page in `check-budgets`, and keep
  S3 time-boxed to one week; if it overruns, the fallback is Astro with the same `docs/` and the same `marked` renderers.
- **SvelteKit 3 is new.** Config moved to `vite.config.ts`, `$lib` was removed, the toolchain is Vite 8 with Rolldown,
  and most tutorials describe the older setup. Read the official docs, not tutorials.
- **Untested in the spike:** `vite dev` with docs outside the app folder, prerendered `+server.ts` endpoints (`llms.txt`,
  `.md` siblings, sitemap, RSS), CodeMirror 6 in Svelte, i18n, and a Cloudflare Pages build. Each is the first task of
  the phase that needs it.
- **Overlap with community looks.** A demo by `wallabyway` (https://wallabyway.github.io/pele-looks-demo/, discussed in Pele
  issue #24) shows seven visual looks (fonts, shadows, idle animation) and built-in icons across about a dozen Pele diagram
  types, shipped as a modified Pele bundle (about 715 KB vs 700 KB stock; options `look`, `animate`, `builtinIcons`; repo
  has only the built files, no source or license shown, not on npm). It is more polished and broader on looks than
  pele-animate. It does not appear to offer explicit step order, step-by-step playback with keys, Tabler icon packs, or a
  build that runs on unmodified Pele (the step-order claim is not fully verified). Response: do not compete on looks;
  position on step order, playback and icons (§0); ask the author for source and license and whether the looks could be
  optional CSS themes over stock Pele plus pele-animate; never copy code without a license. If looks and animation get
  upstreamed, pele-animate shrinks to step order, playback and icon packs, which is still worth shipping.
- **Overlap with pele.run.** Upstream has Playground and API docs for Pele itself. Ours must not re-document Pele.
  Docs link to upstream for layout, syntax and security; our pages cover only what pele-animate adds.
- **Pele coupling.** Step mode and animation rely on Pele's class names (`.pele-node`, `.pele-edge`). A Pele minor can
  break the site as well as consumers; pin `pele` in `site/` and run the docs-examples test on every bump.
- **Step mode is only browser-checked on flowcharts** (HANDOFF open item). Docs must not promise sequence-diagram step
  playback until checked; the playground makes it testable.
- **Accessibility claims** are unverified. `accessibility.md` is written only after a real screen reader and keyboard
  pass.
- **Tabler weight in the playground.** 36 categories, the largest 199 KB; load per category on demand, never all.
- **Naming and trademark.** `pele-animate` references Pele's name. MIT allows it; add the non-affiliation line and give
  kepano a courtesy heads-up before launch (suggested, Daniel's call).
- **Icon naming policy.** `doverunner-*` names stay as the optional pack; if the public docs should not feature the
